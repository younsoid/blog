# 데이터 전처리

#2026-10-05

---

1. version 1.0 
	- 조직 mask: 최대 2,000px 썸네일에서 밝기 < 220 & 채도 > 0.05
	- 타일: level 0에서 256×256 px 격자, step 256 (겹침 없음)
	- 1차 필터: mask 기준 타일 내 조직 비율 ≥ 50%
	- 2차 필터(실제 픽셀): OpenSlide 빨간 배경(R>150, G·B<60) > 30%면 제거, 조직 픽셀 < 50%면 제거
	- 배율·MPP 정규화 없음 → 20×와 40× 슬라이드의 타일 실제 면적이 다름
	- 염색 정규화: Macenko (EXAONEPath 저장소 macenko_target), 실패 타일은 제외
	- 입력 변환: Resize 256 (bicubic) → CenterCrop 224 → ImageNet mean/std 정규화
	- 타일 PNG 저장 없이 메모리에서 바로 임베딩, 처리 후 원본 .svs 삭제, 중단 시 재개 가능
	- 시험 단계: 슬라이드 1장, 후보 3,266개 중 300개 균등 샘플 → 품질 통과 106개

<grayblock>
  
- 병리 슬라이드 한 장을 작은 정사각형 조각(타일)으로 자른다.
- 조직 찾기: 밝기가 220보다 낮고(255가 완전한 흰색) 채도가 0.05보다 높은 곳을 조직으로 봄
- 타일 정의: 256×256 px 격자 칸의 절반 이상이 조직이면 타일로 남기고 OpenSlide로 한번더 검토
  - 보완필요1: 슬라이드마다 촬영 배율이 다른데 (40배로 찍은 슬라이드는 한 픽셀이 약 0.25마이크로미터이고, 20배로 찍은 슬라이드는 약 0.5마이크로미터)
  1.0은 배율과 상관없이 똑같이 256픽셀씩 잘라서 40배 타일은 한 변이 약 64마이크로미터, 20배 타일은 약 128마이크로미터가 되어 면적으로 4배 차이가 된다.
  즉 어떤 사진은 줌을 당겨 세포 몇 개만 크게 찍었고 어떤 사진은 줌을 빼서 넓게 찍었는데 모델에게는 같은 종류의 사진이라고 보여준 셈이 됨
- 병원마다, 염색한 날마다 분홍과 보라의 진하기가 조금씩 다른데 Macenko 툴을 사용해서 정규화.

</grayblock>
  
### 
  
2. version 2.5 (내장 patchfy)
	- 조직 분할 + 좌표 추출 자동
	- MPP 기준 크기 보정: 0.5 µm/px 기준 256px, 예) 0.2457 MPP 슬라이드는 520px로 잘라 같은 면적
	- MPP 정보가 없으면 0.5로 가정

<grayblock>
	
- 2.5는 조직 찾기, 타일 정의, 좌표 뽑기를 patchfy 함수로 자동 수행
  - 슬라이드 파일에 기록된 배율 정보(MPP, 픽셀당 마이크로미터)를 읽어서 타일이 항상 같은 실제 면적을 담도록 자르는 크기를 바꾼다. 기준은 0.5마이크로미터/픽셀에서 256픽셀.
    그래서 0.2457마이크로미터/픽셀인 40배 슬라이드에서는 약 520픽셀로 잘라 같은 면적을 맞춘다. <line>그러면 사실상 2.5로 돌리는게 더 맞겠다.</line>

</grayblock>

3. 슬라이드 특징 벡터 추출
* 1.0: EXAONEPath 1.0 ViT → 타일당 768차원, 배치 32
	- 출력: 슬라이드별 h5 (features N×768, coords N×2)
* 1.0 슬라이드 요약: 학습 없는 pooling 4종
	- mean (768) / max (768) / mean_std (평균+표준편차, 1536)
	- attention (768): 평균 벡터와의 내적을 softmax 가중치로 사용 → 평균에 가까운 타일 강조, 학습형 attention 아님
	- 출력: brca_slide_level.h5 (960 × 차원)
* 2.5: patch feature 768차원 → slide encoder(component = "slide") → slide_embedding 1536차원
	- 입력: patch features, mask(전부 유효), coords, contour_index
	- multi-omics 정렬로 학습된 genomics-aligned 표현
	- 출력: brca_slide_level_25.h5 (pooled/encoder25, 05와 같은 구조)
* UMAP: 타일 지도(NB 03), 슬라이드 지도(NB 05), 라벨 색칠 없음

<grayblock>

- 슬라이드를 타일링한후 타일을 좌표로 변환한다.
  - 병리 이미지 사전학습 ViT(Vision Transformer) 모델인 EXAONEPath 1.0을 사용한다.
  - 슬라이드마다 타일 수 × 768 크기의 matrix가 생성되므로 (타일수, 768) matrix 960개가 생성된다.
- 슬라이드를 pooling 한다.
  - (타일수, 768) 크기 matrix를 (n,) 크기 벡터로 pooling한다.
  - mean (768) / max (768) / mean_std (1536), attention (768) 4가지로 pooling 했다.
- 2.5를 사용하면
  - 평균, 최댓값같은 범용적인 방법으로 요약하는게 아니라 요약 방법을 학습한 slide encoder로 pooling한다.
  - 결과는 (1,536,) 벡터 960개이다.
  - <line>둘다 해보는게 좋긴 하겠지만 궁극적으로는 2.5를 사용할것같긴 하다.</line>

</grayblock>

4. 전처리 결과
  * GDC BRCA DX 1,133장 중 1.0으로 960장 처리 (84.7%), 환자 910명
    - 슬라이드당 타일 수: 최소 26 / 최대 89,245 / 평균 27,450
  * cf) 라벨 매칭
  	- subtype: 947 / 960 슬라이드
  	- methylation: 642 / 910 환자 (70.5%)
  	- 최종 실험 대상 환자: 334명

<grayblock>

- 유방암 진단용 슬라이드 1,133장 중 1.0으로 960장, 약 85%를 처리. 대상자는 910명
- 작은 파일부터 처리했기 때문에 남은 15%는 가장 큰 슬라이드들이고, 큰 슬라이드는 대체로 조직이 넓은 경우이므로 지금 데이터는 조직이 작은 슬라이드 쪽으로 치우쳐 있다.
- 슬라이드마다 나온 타일 수의 차이가 크다. 적은 것은 26개, 많은 것은 89,245개이고 평균은 약 27,450개.
  - 즉 어떤 슬라이드는 손톱만 한 조직 조각이고 어떤 슬라이드는 큰 절제 조직 전체인것임.
  - 나중에 타일들을 평균 내서 슬라이드 하나의 대표값으로 만들 때 26개로 낸 평균과 9만 개로 낸 평균은 신뢰도가 같을 수 없다. 그래서 2.5의 patchfy를 쓰는게 좋다고 한다.
- 면역 라벨은 960장 중 947장에 붙음. 메틸화 데이터는 910명 중 642명, 약 70%에게 존재.
- 최종 비교 실험은 사진, 메틸화 라벨, 면역 점수 다섯 가지가 모두 갖춰진 사람만 쓸 수 있는데 메틸화 라벨이 중간(intermediate)인 사람도 빠지므로 334명만 최종 분석에 쓰인다.

</grayblock>
